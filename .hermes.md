# SubNation2 — agent guidance

Source of truth hierarchy, safety rules, and the deterministic skill-routing
table for this repository. Highest authority after the platform's own safety
rails: **live environment → this file → `docs/` → code comments.** When a doc
and a live probe disagree, live wins and the discrepancy is reported.

## Project shape

Monorepo (`pnpm` workspaces): `backend/` (Express + TypeScript API, Socket.IO,
worker, idempotent boot migration), `frontend/` (React/Vite SPA served by the
same backend), `shared/` (types + Drizzle schema), `whatsapp-service/`
(OpenWA bridge). Conventional commits with a round tag (`fix(backend): … (R116)`).

- Branch: `main` only. `develop` does not exist even though CI declares it.
- CI is billing-disabled: **run every gate locally before claiming green.**
- `.agents/` and `.hermes/` are gitignored — project skill and this file are
  machine-local by design. Never try to force-add them.
- `render.yaml` / `vercel.json` were REMOVED 2026-10-05 (Vercel/Render fully retired; the Vercel project is deleted). Never resurrect them.

## Test gates (definition of done)

```bash
pnpm lint
pnpm typecheck
pnpm --filter @workspace/api-server exec vitest run
pnpm --filter @workspace/subnation run test:run
pnpm build
```

Plus the OpenAPI↔Express route drift check, Drizzle migration drift, and
`gitleaks` (see `.github/workflows/ci.yml`). ~2300 tests is a healthy total; a
much smaller number means a suite silently did not run — say so.

## Non-negotiables

1. **No `db:push`.** Schema moves only through `backend/src/migrate.ts`
   (idempotent boot reconciler). Migrations are expand-first, safe while the
   previous code is still running. Neon never rolls back.
2. **Money invariants M1–M14** (`docs/FINAL_MONEY_INVARIANTS.md`) are law:
   single-transaction checkout, no negative balance, idempotent top-up,
   `payment_reference` guard on `mobile_transfer`, single-writer inventory,
   domain events after commit. Any change near them requires the money suite.
3. **No automatic deploys.** Deployment, restarts, DNS, Coolify secrets, and
   production data writes are explicit, confirmed, user-ordered actions.
4. **Never expose secrets** in output, logs, commits, or diffs.
5. **Health endpoints live under `/api/healthz*`.** Non-`/api` health paths
   return the SPA HTML.

## Code defect vs operator-only

**You fix:** failing tests, type/lint errors, migration drift, broken routes,
invalid committed config, missing branch references in CI.

**You do not touch — report and stop:** DNS/Cloudflare, VM provisioning,
Coolify secrets, WhatsApp QR pairing, TOTP enrollment, inventory loading,
GitHub billing/Actions, account-level deletion
(`docs/deployment/FINAL_OPERATOR_INPUTS.md`).

## Skill routing table (deterministic — follow this, not the index hint)

The Skills index is a **catalog**. Load the skill whose trigger matches the
current phase; do not load skills "just in case", and do not reload a skill
once its result is known. Max 3 concurrently unless a skill explicitly chains
the next one.

| Phase / task | Load | Evidence that closes it |
| --- | --- | --- |
| Repo/orientation, "what is this" | (none — read this file + `README.md`) | structure + branch + gates restated |
| Bug, error, flaky test, regression | `systematic-debugging` (else `debugging-and-error-recovery`) | original failure path re-run and green |
| Write/fix code | `test-driven-development` + `verification-before-completion` | targeted then full gates |
| Review someone's diff (asked for critique) | `receiving-code-review` / `requesting-code-review`; **first** `code-review-and-quality` | findings with file:line |
| Simplify/refactor | `code-simplification` (over `simplify-code`) | behaviour unchanged, tests green |
| Ship a change | `finishing-a-development-branch` | gate results + diff summary |
| Browser/UI verification | `playwright-cli` (over `agent-browser`) | snapshot/screenshot captured |
| Dependency CVEs | `osv-dependency-scan` | JSON parsed, advisories listed |
| Container/IaC/secret scan | `trivy-security-scan` | JSON parsed, counts reported |
| Source security audit | `semgrep-static-analysis` | `errors` read, not just `results` |
| Production state / deploy questions | `coolify-operations` + `subnation-production` | JSON field + command cited |
| Production incident | `subnation-production` → `systematic-debugging` → `investigate` | root cause with reproduction |
| Multi-phase autonomous run | `dynamic-workflow` | phases tracked, each verified |
| Build a UI from scratch | `using-superpowers` → `21st-ai`-style flow → `playwright-cli` | rendered + screenshot |
| Architecture/plan before coding | `brainstorming` → `writing-plans` | written plan, then execute |
| Deploy/rollback operator request | **stop**: report operator-only boundary | user decision recorded |

Precedence when two skills overlap: the more specific wins (table above).
Caveman, Ponytail, and rtk-rewrite run as middleware/hooks regardless of this
table — do not re-implement them as skills.

## Verification before "done"

- Re-run the exact failing path; "should pass" is not evidence.
- Cite command output for every claim about this environment.
- `git status` clean of unrelated edits; `git diff` reviewed before finishing.
- If blocked, report the blocker with the command that produced it. Never
  fabricate test output, logs, or completion.
