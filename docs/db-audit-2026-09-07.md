# الجولة الخامسة — التدقيق الحي لقاعدة البيانات (2026-09-07)

> **النطاق الجديد كلياً:** للمرة الأولى اكتمل الفحص باتصال مباشر بقاعدة بيانات **Neon الإنتاجية** (PostgreSQL 17.11، 35 جدولاً، 11MB). كل الجولات السابقة (1-4) فحصت الكود والموقع الحي فقط — هذه الجولة فحصت **البيانات نفسها**: سلامة المال، حالة التشفير، التسلسلات، الجلسات، النظافة التشغيلية.
> **المنهجية:** فحص SQL مباشر للقراءة فقط (سكربتات `db_deep_inspect.py` + `db_integrity_audit.py`) → مقابلة النتائج مع ادعاءات الكود → إصلاحات عبر نظام الهجرات القياسي (migrate.ts + drizzle 0006) → 18 اختبارًا جديدًا يثبّتون العقود.

## 1. نتائج فحص الإنتاج — الأرقام الحية

### ✅ سلامة المال: مثالية 100% (أهم نتيجة اطمئنان)

| الفحص | النتيجة |
|---|---|
| رصيد كل مستخدم مقابل مجموع قيود الـledger | **12/12 مستخدمًا تطابق تاماً (mismatch = 0.00)** |
| سلسلة القيود (balance_before = آخر balance_after لكل مستخدم) | **صفر انكسارات** |
| كل شحن معتمد له قيد ائتمان (wallet_topup → wallet_ledger) | **4/4 مربوطة** |
| مخزون مباع بلا طلب / مخزون بيع مرتين | **صفر / صفر** |
| كل طلب مرتبط بصف مخزون | **3/3** |
| صحة التسلسلات (last_value ≥ max(id)) لكل 30 جدولاً | **كلها سليمة** |

### 🔴 الاكتشافات الحرجة

1. **`orders.delivered_password` نص صريح في 3/3 طلبات** — إصلاح H2 (الجولة الأقوى) يشفّر الكتابات الجديدة فقط، وتعليق الكود نفسه ادّعى "no backfill needed, reads keep working". القراءة تعمل فعلاً، لكن **هدف الأمان** (تسريب نسخة احتياطية = كشف كل الحسابات المسلّمة) ما زال منتهكًا للصفوف القديمة. كلمات مرور حقيقية ("TestPass!2...") كانت مخزنة خامًا.
2. **321 تنبيه أدمن غير مقروء** (244 `no_stock` + 77 `low_stock`، منها 111 أقدم من 7 أيام) لـ~6 منتجات — نتيجة **علة إزالة تكرار مزدوجة**:
   - `stockWatcher.ts` كان يزيل التكرار بمجموعات **في الذاكرة فقط** (`alertedZero`/`alertedLow`) — تُصفَّر مع كل إعادة تشغيل، وRender المجاني يعيد التشغيل باستمرار (≈40 دورة إقلاع في 12 يومًا).
   - `cron.ts` الوظيفة #1 كانت نظام تنبيه مخزون **ثانٍ موازٍ بلا أي إزالة تكرار إطلاقاً** (SELECT كل منتج <5 مخزون + INSERT لكل واحد، يوميًا).

### 🟠 النتائج المتوسطة

3. **لا تنظيف للجلسات المنتهية إطلاقاً** — 38 صفًا (12 مستخدمًا، أول انتهاء 2026-09-24). الجدول ينمو أحادي الاتجاه مع كل تسجيل دخول للأبد (لا cron ولا reaper، بعكس OTPs/risk/copilot التي لها reap).
4. **الأدمن الوحيد (ahmadmedo, permissions ["all"], is_active) بلا TOTP** — إصلاح H10 حصّن مسار التحقق 2FA لكن أقوى حساب في النظام ما زال يدخل بكلمة مرور فقط.
5. **جودة بيانات الكتالوج**: 18/19 منتجًا بلا `image_url`، 0/19 بوصف طويل أو FAQ، 18/19 بلا `cost_price`. الواجهة تتحمل الغياب بأناقة (بديل فئة + تدرج في ProductCard) — لكن هذه فجوة **محتوى** يحلها أنبوب enrichment 012 الموجود (يتطلب `WORKER_TIER=true` + `ENRICHMENT_RUNNER_ENABLED=true`).
6. منتجات 13-17 + 19 نشطة بلا أي مخزون (مصدر إطلاق سابق لأوانه لتنبيهات no_stock).

### 🟡 ملاحظات

- `inventory` مشفّرة سليمة (63/63 صفًا بصيغة `iv:tag:ct`)، `openwa_sessions`/`system_settings` موجودة فعلاً في الإنتاج (تأكيد حي لـP0-5).
- `users.email` بلا قيد فريد (فهرس عادي) — القرار: advisory فقط (الفرادة محصّنة في `user_auth_identities.provider_uid`)؛ العمود مُجَمَّل عرضياً وتغييره يخاطر بجريان إعادة تسجيل مقبول.
- كوبون `QATEST10` نشط في الإنتاج (اختباري) — يُنصح بتعطيله يدويًا.
