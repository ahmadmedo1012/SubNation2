# تدقيق UX — صفحات المتجر ورحلة الشراء (Storefront + Purchase Journey)

> **تاريخ:** 2026-09-06 | **المصدر:** خطة `docs/subnation-ux-world-class-plan-2026-09-06.md` الفريقان 1 و2
> **المنهجية:** جرد كامل (لا عيّنة) لكل صفحات المتجر + رحلة الشراء عبر 4 وكلاء تدقيق متوازيين، ثم إصلاح مركّز.
> **الحالة:** ✅ الإصلاحات منفَّذة ومُتحقَّق منها محلياً (lint/typecheck/39 اختبار/build) — التحقق الحي بعد النشر.

## أولاً — الاكتشاف الحرج (الفريق 2): رحلة السلة كانت مساراً ميتاً

`CartProvider.addItem` لم يكن مستدعى من أي مكوّن إنتاجي — **لا يوجد زر "أضف للسلة" في أي مكان**. بطاقات المنتجات كانت روابط فقط، صفحة المنتج تشتري مباشرة، وصفحتا `/cart` و`/checkout` + شارة السلة في الـNavbar كانا كوداً ميتاً يظهر فارغاً دائماً.

**الإصلاح المنفَّذ:**

1. **ProductCard.tsx** — أُعيدت هيكلة البطاقة: تفاصيل المنتج `<Link>` + زر **"أضف للسلة"** حقيقي `<button>` **شقيق** للرابط (HTML سليم، قابل للوصول بلوحة المفاتيح، لا تداخل interactive-in-interactive). الزر يضيف للسلة + toast تأكيد + تحديث فوري لشارة الـNavbar.
2. **product.tsx** — زر ثانوي outline "أضف للسلة — أكمل الشراء مع منتجات أخرى" في CTA سطح المكتب (الشريط اللاصق للجوال بقي شراءً مباشراً متعمداً).
3. **cart.tsx** — زر X عند الكمية=1 كان **no-op** (يستدعي `handleUpdate(id, 0)` الذي يرجع مبكراً) → الآن يحذف المنتج فعلاً + aria-label "حذف المنتج". زر الإفراغ أضيف له spinner + "جارٍ الإفراغ...".
4. **checkout.tsx** — إعادة كتابة رحلة المال (انظر القسم الثالث).

## ثالثاً — إصلاحات صفحات المتجر العامة

### حالات الخطأ مميزة عن الفراغ (كان الانقطاع يظهر كـ"لا نتائج")

- **home.tsx** — فرع `isError` كامل: بطاقة "تعذّر تحميل المنتجات" + WifiOff + زر "إعادة المحاولة" (refetch)
- **category.tsx** — نفس النمط "تعذّر تحميل منتجات الفئة"
- **flash-sales.tsx** — نفس النمط "تعذّر تحميل العروض"
- **product.tsx** — فرز صريح: **404 حقيقي** (سهم يحمل `status=404`) → "المنتج غير موجود" / **أي خطأ آخر** → "تعذّر تحميل المنتج" + إعادة محاولة
- **home.tsx** — هيكل الـhero اللانهائي عند فشل `/me` → `userError` يكسر الـskeleton ويعرض hero الزائر (حالة صادقة قابلة للتصفح)

### عدّاد flash-sales (كان N مؤقت لكل بطاقة + حلقة إعادة render أبدية بعد انتهاء العرض)

- مؤقت واحد على مستوى الصفحة يُمرَّر للبطاقات + `clearInterval` نهائي عند الوصول للصفر + `tabular-nums` لأرقام لا تهتز عرضاً
- بطاقة بلا slug كانت تذهب لـ`/` → الآن `/product/{id}`

### layout/CLS

- **`mobile-nav-safe-pad` كان يقتل `md:pb-0` في كل مقاسات الشاشة** (تحقُّق فعلي في CSS المبني: قاعدة المكون تُصدر بعد قواعد Tailwind بنفس الـspecificity) → **فجوة شبح 72px على سطح المكتب لكل مستخدم مسجَّل** + مزدوج مع فوتر mt-12. **الحل:** قصر الأداة على `@media (max-width: 767.98px)` في index.css + توثيق القاعدة لكل الأدوات المحمولة
- **home.tsx:739** — spacer مزدوج `mobile-nav-safe-pad` فوق padding الـmain نفسه (≈144px موتى على الجوال + 72px على سطح المكتب) → حُذف؛ مسافة تنفّس للزوار فقط (`h-6 md:h-0`)
- **`mobile-product-pad-auth` كان يحسب ارتفاع الـnav مرتين** (68+60+safe فوق 72+safe من main ≈ 76px فائضة) → القيمة الآن `68px + 0.5rem` لأن main يحجز مساحة الـnav أصلاً؛ مع قصرها على <640px (الشريط اللاصق `sm:hidden`)
- **الجمجمة والأشكال (route-skeletons):** شكل `detail` العام (max-w-4xl + 4:3) كان يقفز إلى صفحة منتج max-w-xl/16:9 (**انزياح 256px أفقي في أكثر الصفحات زيارة**) → شكلان جديدان دقيقان: `product` (max-w-xl/16:9/بطاقة CTA) و`order` (max-w-2xl/صفوف)؛ `/loyalty` أبقى `detail` المطابق
- **flash-sales container:** max-w-5xl → **max-w-6xl** (توحيد مع home/category وشكل catalog skeleton — كان سبب قفزة الحواف)
- **Footer:** `mb-[72px]` أقل من ارتفاع الـnav+safe-inset على أجهزة home-indicator → `mb-[calc(60px+env(safe-area-inset-bottom))]`
- **MobileNav على /login و/register بدون padding الـmain** (يظهر الشريط ويغطي المحتوى) → حُذف شرط `!isAuth` من padding الـmain (محاذاة مع شرط ظهور الـnav)
- **Navbar cart badge:** `text-primary-text` يجعل الرقم **غير مرئي في الثيم الفاتح** (نفس قيمة --primary تقريباً) → `text-primary-foreground`

### مكونات مشتركة

- **NotificationBell (النمط المرجعي للأيقونات):** لوحة سطح المكتب كانت **تُقتطع خارج حافة الشاشة اليسرى** على 480–1300px (مرساة حافة-يمين تنمو يساراً بينما الجرس في أقصى يسار RTL) → مرساة الحافة اليسرى + clamp. الصفوف div قابلة للنقر بلا مسار لوحة مفاتيح → `<button>` حقيقي + focus ring. الطلبات بلا deep-link كانت تفقد زر الإجراء → fallback `/orders`. شارة unread `text-white` → `text-primary-foreground`
- **FlashSaleBanner:** الرابط كان `/` (السهم "اذهب للعرض" كان يكذب) → `/flash-sales`؛ زر الإغلاق ~20px → p-2.5 (≥24px AA)
- **Toaster (sonner.tsx):** كان يستورد `useTheme` من `next-themes` **بلا مزوّد mounted إطلاقاً** → التوستات تتبع ثيم نظام التشغيل لا ثيم التطبيق → `@/lib/theme` (sn_theme الحقيقي)
- **dialog.tsx / alert-dialog.tsx:** `sm:text-left` يحاذي عناوين الحوارات العربية **يساراً** على سطح المكتب بينما التطبيق كله start/يمين → `sm:text-start`؛ توحيد `backdrop-blur-sm` بين البدائين (كانت موجودة في أحدهما فقط)
- **MobileNav:** `aria-current="page"` للتبويب النشط + حجم نص التسمية 9.5px → 10px (حد أدنى معقول)

### أمان الشراء (double-click)

- زر الشراء في product.tsx كان محمياً أصلاً (`disabled={isPending}` + "جارٍ المعالجة") — حُفظ
- زر كوبون المنتج محمي أصلاً — حُفظ + **إغلاق ثغرة Enter المزدوج** (كان يمكن إطلاق POST تكرار أثناء validation جارٍ)
- زر تحديث status.tsx (GET idempotent، خطر منخفض) — موثَّق في التدقيق، الإصلاح مؤجَّل لأولوية أدنى

## رابعاً — بنود موثَّقة فقط (خارج نطاق UX، لا تُكرَّر من PROJECT_OVERVIEW)

- **Idempotency-Key على POST /api/orders** (lib/idempotency.ts موجود لكن مربوط بمسارات الأدمن فقط) — يتطلب تغييراً خلفياً + اختبارات تكامل؛ **الحماية الحالية client-side كافية لمتطلب "منع النقر المزدوج" لكنها لا تحمي من retry الشبكة** — موصى به كخطوة تالية
- **الكوبون في checkout يُتحقق منه عند التأكيد فقط** (لا زر تحقق مسبق) — مقصود: الكوبون يعتمد على المنتج والسلة متعددة المنتجات؛ ملاحظة صادقة أُضيفت في الواجهة
- **dead code في cart.tsx:** `serverItems`/`ServerCart` (السلة الخادمية غير موصولة — مسارات cart الخلفية موجودة من baff5d0 لكن الواجهة محلية) — موثَّق، السلة المحلية تكفي لرحلة الشراء الحالية
