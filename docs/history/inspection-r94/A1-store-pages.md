> **الوكيل:** A1 (قراءة فقط — لم يُعدَّل أي ملف كود)
> **النطاق:** frontend/src/pages (21 صفحة) + hooks/* المستخدمة منها + lib الداعمة (cart/utils/errors/theme) + index.css (الرموز) — مع تحقق خلفي مقتبس من backend عند الحاجة.

### 1. [P2] بوابة «رصيد غير كافٍ» في checkout تقارن رصيدًا مقابل مجموع فاصلة عائمة غير مقرَّب — قد تحجب مستخدمًا قادرًا على الدفع وتعرض «الناقص 0.00 د.ل»
**الملف:السطر:** `frontend/src/lib/cart.tsx:122` + `frontend/src/pages/checkout.tsx:170,453`
**الدليل:**
```ts
// lib/cart.tsx:122 — مجموع خام بلا تقريب
const totalLYD = items.reduce((sum, i) => sum + effectivePrice(i) * i.quantity, 0);
// checkout.tsx:170
const insufficient = !balanceLoading && !balanceError && balance !== null && balance < totalLYD;
// checkout.tsx:453
<p>رصيد المحفظة غير كافٍ (الناقص {formatCurrency(totalLYD - (balance ?? 0))}).</p>
```
في المقابل `cart.tsx:55-56` **يقرِّب** نفس المجموع: `+items.reduce(...).toFixed(2)` — أي أن الكود نفسه يعرف بالمشكلة وعالجها في صفحة واحدة فقط.
**الإثبات الحسابي (Node، أسعار واقعية بكسور من خصومات نسبية):**
- `8.33 × 6 = 49.980000000000004` ← رصيد `49.98` بالضبط ⇒ `49.98 < 49.980000000000004 = true` ⇒ `insufficient=true`
- الفرق المعروض: `49.980000000000004 - 49.98` ⇒ `formatCurrency` ⇒ **«الناقص 0.00 د.ل»** وزر التأكيد معطَّل (`canSubmit=false`, checkout.tsx:173-177).
- كذلك `0.1+0.2 = 0.30000000000000004` و`12.99+34.99 = 47.980000000000004`.
**الأثر:** مستخدم رصيده مساوٍ تمامًا للمجموع (أرصدة بكسور تنتج طبيعيًا من الاستردادات: قيم مثل 29.74 تُعاد للمحفظة) يُمنع من الشراء برسالة غير منطقية «الناقص 0.00 د.ل» — على مسار المال مباشرة.
**الإصلاح المقترح:** في `lib/cart.tsx`: `const totalLYD = Math.round(items.reduce(...) * 100) / 100;` (توحيدًا مع cart.tsx:56)، وفي checkout.tsx:170 قارن القيم المقربة: `balance < Math.round(totalLYD*100)/100` — أو أزل البوابة أصلًا واعتمد على استجابة الخادم (INSUFFICIENT_BALANCE) لأن البوابة عرضية فقط.
