## 2. الحادثة المركزية — قاتل النشر مرة أخرى (وأُغلق نهائيًا)

نشر 65b8acc (docs-only) فشل الساعة 01:07 UTC بسبب `CREATE EXTENSION pg_trgm` → `25006 cannot execute CREATE EXTENSION in a read-only transaction` → تصنيف "critical" → `process.exit(1)`. **خلال هذه الجولة نفسها** دخلت القاعدة نافذة قراءة-only حية عند 10:00 UTC (تعطّل سكربت عمليات البيانات مؤقتًا) — تأكيد مباشر أن الحالة تتكرر دوريًا مع Neon pooler.

**الإصلاح ثلاثي الطبقات (B7 §2.2 — مُنفَّذ بالكامل):**
1. **بوابة قابلية الكتابة**: `pg_is_in_recovery() + transaction_read_only` قبل قفل Redis — اقتراع كل ثانيتين حتى 120 ثانية (MIGRATION_WRITE_WAIT_MAX_MS).
2. **تصنيف "transient"**: SQLSTATE 25006/0800x/57P0x + نصوص → إعادة تشغيل كاملة للترحيلات 5s→15s→45s (الأمان مثبت: كل عبارة idempotent).
3. **صفر DDL في الإقلاع المستقر**: فحص pg_extension قبل CREATE + إزالة دورة بعث/إسقاط جدول otps (كانت ~80 عبارة DDL كل إقلاع).

**نتيجة القياس الحي**: الترحيلات انخفضت من 83 عبارة متسلسلة إلى إقلاع نظيف في **6.9 ثانية** (كان 1-3 ثوانٍ + هشاشة كل إقلاع).

## 3. حادثة ثانية اكتُشفت وأُصلحت أثناء النشر — حارس الوحدة-الرئيسية الكاذب
