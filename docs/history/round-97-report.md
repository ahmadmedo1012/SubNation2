## 2. الاكتشاف الحاسم للجولة: الموت الصامت

**طبقة المجدولات كانت ميتة في الإنتاج منذ 2026-09-08** — اكتشفها R97-A3 وأكدها R97-A6 سطرًا-سطرًا:
- `REDIS_URL` غير موجود في بيئة Render المستعادة (استعادة الجولة 5 لم تُرفق الخدمة) — **وخدمة Redis غير منشأة أصلًا** (تعذر إنشاؤها عبر API — الخطة غير متاحة).
- `scheduler-coordinator.ts` يرد `no_client` للأبد (fail-closed) بينما الترحيلات fail-open → التطبيق يعمل ظاهريًا والمجدولات مظلمة.
- **الأثر**: 13 cron + 3 watchers + مقيّم التنبيهات + نبض القلب كلها ميتة · صفر تنبيهات مخزون رغم 5 منتجات بمخزون صفر · 5 OTP منتهية · 5 جلسات أدمن منتهية · **مسار ربط Firebase يرد 503 على المستخدمين النهائيين**.

**الإصلاح (97-F1)**: قيادة PostgreSQL lease — جدول `scheduler_leader_lease` (CAS بعبارة واحدة آمنة عبر Neon pooler، TTL 60s، refresh 20s مع تحقق holder) — المجدولات تعمل الآن **بدون Redis إطلاقًا**، وRedis يبقى المسار الأساسي إن وُجد مع تسليم تلقائي عند عودته. أُضيفت one-shots الإقلاع الناقصة (OTP/جلسات أدمن/flash sales) لتنظيف ما تراكم أثناء الموت.

## 6. دروس تشغيلية جديدة

- **استعادة متغيرات البيئة عبر API تحذف الربط منService** (REDIS_URL من subnation-redis) — أي استعادة مستقبلية يجب أن تعيد إرفاق المتغيرات المشتقة، أو تُستبدل بمسار code-side fallback كما فعلت الجولة 97.
- **خدمة Redis على Render غير قابلة للإنشاء عبر API** بالتوكن الحالي — الاعتماد الخلفي الوحيد الصامد بدون خدمات إضافية هو PostgreSQL (Neon).
- **مراقبة «الصمت» أهم من مراقبة الأخطاء**: التطبيق الأخضر مع مجدولات ميتة — الحل: مراقب القناة (97-F3) + سطر قيادة صريح في اللوجز + تنبيه dedupe.
