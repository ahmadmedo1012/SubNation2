## 2. The semantics contract as tested (ADR §5's matrix)

- Single-item checkout: group present, UI unchanged (no divider on 1-order
  groups — the uniform contract, zero client branching).
- Multi-item full success: all N orders share one group; the toast + /orders
  landing (R161-G) unchanged; /orders clusters the run.
- Partial HTTP failure: group contains exactly the k created orders; the
  retry's remaining units reuse the SAME group (frontend lifecycle test).
- Network failure mid-loop: the group SURVIVES (like the unit keys) — the
  retry replays charged units (unit keys, no double charge) and completes
  the remainder under the same group.
- Idempotent replay: `replayOriginalOrder` returns the stored row's group
  verbatim (service test).
- Same unit key + re-minted group: the body changed → the route's
  `canonicalBodyHash` differs → classified 409 `IDEMPOTENCY_KEY_REUSE` —
  fail-closed by construction (pinned at BOTH the service layer — the
  simulated hash — and the route layer, where the hash is genuinely
  computed from the body).
- Skipped-by-other-tab units: not created → not in the group.
- Historical orders: NULL group → singleton rendering, byte-identical
  (pinned).
- Refund: per-order, untouched (RefundService never reads the column).

## 3. The one design deviation from the unit-key idiom (disclosed)

The group's **load** is subset-tolerant, not exact-fingerprint
(`checkout-group-key.ts` docblock): the unit keys' exact-match discipline
exists to stop double charges; applying it verbatim to the group would
FRAGMENT the exact scenario the ADR built it for — a partial failure fully
completes one line (removed from the cart), so the retry's remaining lines
are a *subset* of the original basket and an exact basket-fingerprint
match would re-mint. The overlap check (current lines ∩ stored lines ≠ ∅)
keeps the retry in the SAME group while still isolating a genuinely
different basket (and other tabs' different baskets) within the TTL.
Coupon removal mid-retry deliberately does not re-mint (not part of the
fingerprint — same purchase intent, ADR §2.1.1). A >10-min-late retry
mints a fresh group alongside fresh unit keys (the 98-F2 trade-off,
applied consistently — pinned by the TTL test).

## 7. Deploy behavior (what happens on merge)

Neon never rolls back; the stage is expand-first (nullable, no default,
partial index, probe-gated). The Coolify webhook builds + deploys on
push; the boot converges the column + index in one reconcile; steady
state re-boots issue zero DDL. Mixed-version clients during the deploy
window converge naturally (NULL groups from old code, populated from new
— both render correctly; the V1-M32 precedent). The frontend change is
purely additive: old bundles send no `order_group_id` (NULL groups), new
bundles do — one SHA window where both live is the designed transition.
