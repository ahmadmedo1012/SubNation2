### L1-2 · P3 · Topup approval outside the waiting modal dead-ends the checkout-return journey — the stashed `?return=` intent has no consumer once the modal is gone

- **Evidence:** the ONLY path from a failed checkout to topup is `components/checkout/PaymentMethodCard.tsx:102` `href="/wallet?return=/checkout"` («اشحن المحفظة ثم عُد لإتمام الطلب»). `pages/wallet.tsx:119-133` stashes it in sessionStorage (`subnation_topup_return`). The **only** consumer is `TopupWaitingModal`'s `onApprovedContinue` (wallet.tsx:825-833), which is armed exclusively by `setWaitingTopupId(created.id)` on a **new** submit (wallet.tsx:501). Operator approval routinely takes minutes (the modal itself promises "بحد أقصى 30 دقيقة"), while the modal grants dismissal agency after 10 s (`TopupWaitingModal.tsx:51` `DISMISS_AFTER_SECONDS`). Every approval that lands after dismissal / navigation / tab-death surfaces only as: the socket toast (`use-socket.ts:141-148`, itself page-scoped to wallet+order-detail) or the bell notification, whose deep link is fixed `/wallet` (`topup.service.ts:626-630`). Nothing on /wallet, the toast, or the notification offers the way back to the still-pending cart — the buyer must manually re-find /cart → /checkout. Worse, the un-consumed sessionStorage intent survives indefinitely and is silently consumed by a **future, unrelated** topup's modal (navigating the user to a possibly-stale `/checkout` intent in the same long-lived tab).
- **Root cause:** the return intent is modal-lifetime-bound; no approval surface reads it after the modal closes.
- **Proposed fix (smallest):** in `use-socket.ts`'s `topup-updated` approved branch (and/or wallet.tsx's approval render path), when `sessionStorage.subnation_topup_return` exists, surface an affordance — e.g. the approval toast gains a «متابعة الشراء» action, or /wallet renders a persistent return banner while the intent is armed and the latest topup is approved. Plus: expire the entry (consume-or-clear) so it cannot fire on a stale intent.
- **Test requirement:** wallet page with a stashed return intent + an approved topup **without** an open modal renders the return affordance; the intent is cleared after consumption or cart-empty.
- **Risk:** low — presentation-only; the money path (balance invalidation) already works on all these branches.
