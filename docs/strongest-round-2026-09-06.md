## 3. الجولة الثانية — الفحص العكسي (red-team على إصلاحاتنا)

متخصص واحد فحص **كل إصلاح جديد بحثاً عن تجاوزات** واكتشف 7 ثغرات في الإصلاحات ذاتها (أُصلحت فوراً في `31b4b08`):

1. 🔴 **CRITICAL:** رمز 2FA المؤقت كان جلسة إدارية كاملة — كلمة المرور وحدها تكفي لتجاوز التحقق بخطوتين بالكامل. الآن `requireAdmin` يرفض `isTemp`.
2. 🟠 تسجيل الخروج لم يكن يحذف صف الجلسة (ثغرة H1 كانت نصف مغلقة). الآن يُحذف.
3. 🟠 قاعدة بيانات جديدة: أول أدمن يولد بصلاحيات فارغة (قفل أبدي). الآن `["all"]`.
4. 🟡 قناع cidr6 معكوس — عناوين CF IPv6 الحقيقية لا تتطابق أبداً (عاصفة 429). أُصلح وتحقق رقمياً.
5. 🟡 `/admin/tickets` بنتيجة فارغة → `IN ()` → خطأ 500. حُرس.
6. 🟡 النص المشفر قد يفيض عمود 255 → فشل الشراء. وُسِّع إلى 512 + ALTER موضعي.
7. 🟡 قاعدة p95 كانت تقرأ شكل prom-client الخطأ (قاعدة ميتة). أُعيدت بتحليل الشكل الفعلي.

## 5. الجولة الثالثة — عقود API + SEO + ترويسات

- 🔴 **نقطة نهاية شبح:** زر تعديل المخزون في لوحة الإدارة كان يستدعي مساراً غير موجود — كل تعديلات المخزون تفشل منذ كتابته. نُفِّذ المسار بمنطق مخزون صادق (تقليل=حذف، زيادة=رفض موجّه).
- 🔴 **التكرار الآمن (idempotency):** POST /api/orders الآن بوسيط idempotency (موضوع userId) + مفتاح لكل وحدة طلب — إعادة المحاولة الشبكية لم تعد خصماً مزدوجاً.
- مغلفات الأخطاء تحمل code (محفظة 429، إدارة، حدود المعدل)
- search الإداري الصامت: /admin/orders و/admin/products ينفذان البحث فعلياً
- noindex لـ /cart و/checkout (ميتا + robots.txt — تحقق حي)
- sitemap يضم /flash-sales · ItemList بـ slugs · og:image=opengraph.jpg
- ترويسة Permissions-Policy · CORS يغلق مقاوم في الإنتاج · حد 5 تذاكر/ساعة
- **استبدال react-helmet-async بإدارة رأس مباشرة** — اكتشاف الجولة: تحت React 19 لم تكن وسميات الصفحة تُطبَّق إطلاقاً (3× title في بناء الإنتاج، تحقق حي بالمتصفح). بعد الاستبدال: title واحد + JSON-LD المنتج + canonical المسطّح + og:type=product — كلها حيّة ومؤكدة.
